## JavaScript কী?

JavaScript হলো একটি **programming language** যা দিয়ে computer-কে instructions দেওয়া হয়।

```
HTML  → বাড়ির দেয়াল ও কাঠামো (Structure)
CSS   → বাড়ির রং ও ডিজাইন (Style)
JS    → বাড়ির বিদ্যুৎ, সুইচ, ফ্যান (Behaviour)
```

## ইতিহাস

```
1995  →  Brendan Eich (Netscape) মাত্র 10 দিনে তৈরি করেন
         নাম: Mocha → LiveScript → JavaScript

1997  →  ECMAScript (ES1) — আন্তর্জাতিক standard
         ECMA International নিয়ম নির্ধারণ করে

2009  →  Node.js তৈরি (Ryan Dahl)
         JavaScript প্রথমবার browser-এর বাইরে গেল

2015  →  ES6 / ES2015 — বিশাল পরিবর্তন
         let, const, arrow fn, class, Promise...

2016+ →  প্রতি বছর নতুন version: ES2016 → ES2024
```

> ⚠️ **গুরুত্বপূর্ণ:** JavaScript আর Java **সম্পূর্ণ আলাদা** ভাষা। নামের মিল আছে, কিন্তু কোনো সম্পর্ক নেই।

## JavaScript Engine কীভাবে কাজ করে

> CPU শুধু Binary (0, 1) বোঝে। JavaScript Engine সেই কাজটি করে — তোমার code → machine code।

### সবচেয়ে বিখ্যাত: **V8 Engine** (Google)
- Chrome browser-এ ব্যবহৃত
- Node.js-এ ব্যবহৃত

### Execution Pipeline

```
┌─────────────────────────────────────────────┐
│           তোমার JavaScript Code              │
│        let x = 5 + 3;                       │
└──────────────────┬──────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────┐
│                PARSER                        │
│  Code → Tokens → AST                        │
│                                             │
│  AST (Abstract Syntax Tree):                │
│         Assignment                          │
│        /         \                          │
│      'x'      BinaryOp(+)                   │
│               /        \                    │
│              5           3                  │
└──────────────────┬──────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────┐
│         IGNITION (Interpreter)               │
│         → Bytecode তৈরি করে                │
│         (দ্রুত শুরু করার জন্য)             │
└──────────────────┬──────────────────────────┘
                   │
          (Hot Code detected)
                   │
                   ▼
┌─────────────────────────────────────────────┐
│         TURBOFAN (JIT Compiler)              │
│         → Optimized Machine Code            │
│         (maximum performance)               │
└──────────────────┬──────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────┐
│                  CPU                         │
│          Binary execute করে                 │
│          Result: x = 8                      │
└─────────────────────────────────────────────┘
```

---

## JIT Compilation

> **JIT = Just-In-Time Compilation**
> JavaScript interpreted + compiled — দুটো মিলিয়ে কাজ করে।

| পদ্ধতি | কীভাবে কাজ করে | উদাহরণ |
|--------|----------------|---------|
| **Interpreted** | Line by line পড়ে execute | Python (traditional) |
| **Compiled** | আগে সব compile → তারপর চালায় | C, C++ |
| **JIT (JS)** | প্রথমে interpret, hot code compile | JavaScript V8 |

**সুবিধা:**
- প্রথমবার দ্রুত শুরু হয় (interpret)
- বারবার চলা code আরো দ্রুত হয় (compile)

## Node.js কী?

```
NODE.JS  =  V8 Engine  +  libuv
```

```
┌──────────────────────────────────────────┐
│              NODE.JS                      │
│                                          │
│  ┌──────────────┐  ┌──────────────────┐  │
│  │  V8 Engine   │  │     libuv        │  │
│  │              │  │                  │  │
│  │  JavaScript  │  │  • File System   │  │
│  │  Execute করে│  │  • Network I/O   │  │
│  │              │  │  • Timer         │  │
│  │              │  │  • Thread Pool   │  │
│  └──────────────┘  └──────────────────┘  │
│                                          │
│  + Built-in APIs: http, fs, path, os...  │
└──────────────────────────────────────────┘
```

**Ryan Dahl** 2009 সালে Node.js তৈরি করেন কারণ:
- Browser-এর বাইরে JavaScript চালাতে চেয়েছিলেন
- Non-blocking I/O দিয়ে fast server বানাতে চেয়েছিলেন

## প্রথম Code

```javascript
// এটি একটি comment — Engine ignore করে, human-এর জন্য

console.log("আমি JavaScript শিখছি!");   // text print
```

**Output:**

### কেন এই output?
| Line | কী হচ্ছে |
|------|---------|
| `console.log("text")` | Screen-এ text দেখায় |
| `console.log(5 + 3)` | JavaScript আগে `5+3` calculate করে → `8` পায় → দেখায় |
| `console.log("a", "b")` | দুটো argument একসাথে space দিয়ে দেখায় |

## Interview Questions

**Q1: JavaScript কি interpreted নাকি compiled language?**
> দুটোই — JIT (Just-In-Time) compilation ব্যবহার করে। প্রথমে Ignition দিয়ে interpret করে Bytecode বানায়, তারপর TurboFan দিয়ে hot code-কে optimized Machine Code-এ compile করে।

**Q2: V8 Engine কী এবং কোথায় ব্যবহৃত হয়?**
> Google-এর তৈরি JavaScript engine। Chrome browser এবং Node.js উভয়েই ব্যবহৃত।

**Q3: Node.js কী?**
> V8 Engine + libuv library-র combination। JavaScript-কে server-side-এ non-blocking, event-driven ভাবে চালানোর runtime।

**Q4: ECMAScript কী?**
> JavaScript-এর আন্তর্জাতিক specification/standard। ECMA International নামক সংস্থা প্রতি বছর নতুন feature যোগ করে।

**Q5: JIT Compilation-এর সুবিধা কী?**
> Fast startup time (interpret) + বারবার চলা code automatically optimize হয় (compile)। Best of both worlds।

## 🔵 Step 2 — Junior Developer Interview

> কোম্পানি দেখতে চায়: Engine সম্পর্কে ধারণা আছে? Node.js জানো?

---

### ❓ প্রশ্ন ১
**"JavaScript কীভাবে execute হয়? Interpreted নাকি Compiled?"**

✅ **আদর্শ উত্তর:**
```
JavaScript JIT (Just-In-Time) Compilation ব্যবহার করে —
মানে দুটোই। V8 Engine-এ দুটো part আছে:

১. Ignition (Interpreter) — প্রথমে code-কে Bytecode-এ
   convert করে দ্রুত শুরু করার জন্য।

২. TurboFan (JIT Compiler) — বারবার চলা "hot" code-কে
   Optimized Machine Code-এ compile করে speed বাড়ায়।

তাই JavaScript-কে না interpreted না compiled বলে —
বলা হয় JIT compiled।
```

---

### ❓ প্রশ্ন ২
**"Node.js কী? Browser JavaScript-এর সাথে পার্থক্য কী?"**

✅ **আদর্শ উত্তর:**
```
Node.js হলো V8 Engine + libuv library। এটা দিয়ে
JavaScript server-এ চালানো যায়।

পার্থক্য:
- Browser JS: DOM access আছে, window object আছে,
  file system access নেই।
- Node.js: DOM নেই, window নেই, কিন্তু file system,
  network, os-level access আছে।
```

---

### ❓ প্রশ্ন ৩
**"ECMAScript কী? ES6 কেন গুরুত্বপূর্ণ?"**

✅ **আদর্শ উত্তর:**
```
ECMAScript হলো JavaScript-এর official specification —
মানে নিয়মের বই। ECMA International এটা maintain করে।

ES6 (2015) গুরুত্বপূর্ণ কারণ এটাতে এসেছে:
let, const, Arrow Function, Class, Promise,
Template Literal, Destructuring, Modules —
এগুলো modern JavaScript-এর ভিত্তি।
```

## 🟡 Step 3 — Mid-Level Developer Interview

> কোম্পানি দেখতে চায়: তুমি কি internally বোঝো? Performance নিয়ে ভাবো?

---

### ❓ প্রশ্ন ১
**"V8 Engine-এ AST কী এবং কেন দরকার?"**

✅ **আদর্শ উত্তর:**
```
AST = Abstract Syntax Tree।

JavaScript code প্রথমে Parser-এর কাছে যায়।
Parser দুটো কাজ করে:
১. Lexing/Tokenizing — code-কে ছোট ছোট token-এ ভাগ করে।
   যেমন: let x = 5 → [let] [x] [=] [5]
২. Parsing — token গুলো দিয়ে tree structure বানায় = AST।

AST দরকার কারণ:
- Raw code text থেকে directly machine code বানানো কঠিন।
- Tree structure থেকে optimization করা সহজ।
- TurboFan এই AST ব্যবহার করে optimize করে।

Babel, ESLint, Prettier — সবাই AST ব্যবহার করে।
```

---

### ❓ প্রশ্ন ২
**"Hot Code কী? TurboFan কখন কাজ শুরু করে?"**

✅ **আদর্শ উত্তর:**
```
V8-এ Ignition Bytecode execute করতে করতে track করে
কোন function বারবার call হচ্ছে। যেটা অনেকবার চলে
সেটাকে বলে "Hot Code" বা "Hot Function"।

TurboFan তখন সেই hot function-কে নিয়ে:
১. Assumptions করে (type guessing)
২. Optimized Machine Code তৈরি করে
৩. CPU directly সেটা execute করে — অনেক fast

কিন্তু যদি assumption ভুল হয় (deoptimization),
TurboFan আবার Ignition-এ ফিরে যায়।
এটাকে বলে "Deoptimization" বা "Bailout"।
```

---

### ❓ প্রশ্ন ৩ — Architecture
**"Node.js কেন single-threaded হয়েও fast?"**

✅ **আদর্শ উত্তর:**
```
Node.js main thread single-threaded কিন্তু libuv-এর
Thread Pool ব্যবহার করে heavy কাজ background-এ করে।

Flow:
১. Request আসলে Event Loop নেয়
২. I/O operation (file read, DB query) → libuv Thread Pool-এ পাঠায়
৩. Main thread block না হয়ে নতুন request নেয়
৪. Background কাজ শেষ হলে callback আসে Event Loop-এ
৫. Result দেওয়া হয়

এই pattern = Non-blocking I/O।
তাই single thread হয়েও হাজার হাজার concurrent request handle করতে পারে।
```

## 🔴 Step 4 — Senior Developer Interview

> কোম্পানি দেখতে চায়: তুমি কি system-level ভাবতে পারো?

---

### ❓ প্রশ্ন ১
**"V8-এর Hidden Classes কী? Performance-এ কীভাবে affect করে?"**

✅ **আদর্শ উত্তর:**
```
V8 object-এর জন্য internally Hidden Class তৈরি করে।
এটা C++ struct-এর মতো — property-র memory layout track করে।

উদাহরণ:
const obj = {};
obj.x = 1;  // Hidden Class C0 → C1 (x যোগ)
obj.y = 2;  // Hidden Class C1 → C2 (y যোগ)

সমস্যা হয় যদি:
const a = { x: 1, y: 2 };  // C0 → C1 → C2
const b = { y: 2, x: 1 };  // C0 → C3 → C4 (আলাদা class!)

একই structure হলে same hidden class share করে → fast।
আলাদা order হলে আলাদা class → memory বাড়ে, slow।

Best Practice: Object property সবসময় একই order-এ initialize করো।
Constructor-এ সব property define করো।
```

---

### ❓ প্রশ্ন ২
**"Node.js-এ libuv Thread Pool-এর default size কত? কীভাবে change করবে?"**

✅ **আদর্শ উত্তর:**
```
Default Thread Pool size = 4।

Change করার উপায়:
UV_THREADPOOL_SIZE=8 node server.js

অথবা code-এ:
process.env.UV_THREADPOOL_SIZE = 8;
// এটা অবশ্যই top-level-এ রাখতে হবে, কোনো async call-এর আগে।

কখন বাড়াবো?
- CPU-bound নয়, I/O-bound heavy operation থাকলে।
- File read/write, DNS lookup, crypto — এগুলো Thread Pool ব্যবহার করে।
- DB queries সাধারণত নিজস্ব connection pool ব্যবহার করে।

সতর্কতা: বেশি thread = বেশি memory + context switching overhead।
CPU core সংখ্যার বেশি দিলে benefit নেই।
```

### ❓ প্রশ্ন ৩ — Design Decision
**"একটা high-traffic API বানাচ্ছো। Node.js vs Go — কোনটা বেছে নেবে এবং কেন?"**

✅ **আদর্শ উত্তর:**
```
Context দেখে সিদ্ধান্ত নিই:

Node.js বেছে নেবো যদি:
- Team-এ JavaScript expertise বেশি।
- I/O-heavy workload (DB, API calls, file)।
- npm ecosystem দরকার।
- Rapid development priority।
- Real-time features দরকার (WebSocket)।

Go বেছে নেবো যদি:
- CPU-intensive computation দরকার।
- Extreme low latency দরকার।
- Memory footprint অনেক কম রাখতে হবে।
- Concurrent goroutine-এর সুবিধা নিতে হবে।

আমাদের current stack যদি JavaScript হয়, Node.js-ই নেবো।
Premature optimization না করে আগে product deliver করবো।
```

### ❓ প্রশ্ন ১
**"আমাদের কোম্পানি সব team-এ Node.js নেবে কিনা — তুমি কীভাবে evaluate করবে?"**

```
একটা RFC (Request for Comments) process ধরে evaluate করবো:

৪. Risk Assessment:
   - Single point of failure?
   - Vendor lock-in?
   - Team onboarding cost?

৫. Pilot Program:
   - একটা non-critical service-এ আগে চালু করবো।
   - 3 মাস metric collect করবো।
   - তারপর broader rollout।

সিদ্ধান্ত: technical merit + business context + team capability
তিনটা মিলিয়ে নেবো। শুধু technical দিয়ে নয়।
```

### ❓ প্রশ্ন ২ — System Design
**"10 million daily active user-এর জন্য Node.js backend কীভাবে design করবে?"**

✅ **আদর্শ উত্তর (High-level):**
```
Layer by layer design করবো:

১. Entry Layer:
   - CDN (Cloudflare) → static asset serve।
   - Load Balancer (Nginx / AWS ALB)।
   - Rate Limiting + DDoS protection।

২. Application Layer:
   - Node.js cluster mode (CPU core × process)।
   - Horizontal scaling (auto-scaling group)।
   - Stateless design — কোনো in-memory session নয়।

৩. Caching Layer:
   - Redis: session, frequently accessed data।
   - Database query result cache।
   - Cache invalidation strategy (TTL + event-based)।

৪. Database Layer:
   - Primary + Read Replicas।
   - Connection pooling (pg-pool, mongoose pool)।
   - Sharding যদি data বড় হয়।

৫. Async Processing:
   - Heavy task → Message Queue (BullMQ / RabbitMQ)।
   - Worker process আলাদা।

৬. Observability:
   - Structured logging (Winston + ELK)।
   - Metrics (Prometheus + Grafana)।
   - Distributed tracing (OpenTelemetry)।

এই design 10M DAU সহজে handle করতে পারবে।
Bottleneck হলে layer-by-layer optimize করবো।
```

===========================================
Lesson : JavaScript Introduction (Lesson 1)
===========================================

Important Points:
- JavaScript একটি Dynamic, Interpreted Language
- Browser + Server (Node.js) দুই জায়গায় চলে
- V8 Engine JS কে Machine Code এ convert করে
- Case Sensitive — Console ≠ console
- Ryan Dahl 2009 সালে Node.js বানান

Definition:
JavaScript = একটি Programming Language যা
Web এর behavior তৈরি করে।

Syntax:
console.log("যা দেখাতে চাও");

Example:
console.log("Hello, World!");

Mistakes:
❌ Console.log() → ✅ console.log()
❌ console.log("Hello" → ✅ console.log("Hello")

Shortcut Tips:
- VSCode এ JS file চালাতে: node filename.js
- Comment: // এক লাইন, /* */ একাধিক লাইন

Interview Tips:
- JS Interpreted কিন্তু V8 JIT use করে
- Node.js = V8 + libuv + built-in modules
- Brendan Eich, 1995, 10 দিনে তৈরি

Summary:
JavaScript দিয়ে Frontend + Backend দুটোই করা যায়।
Node.js হলো Server-side JavaScript runtime।
===========================================


Q1: JavaScript কী?

JavaScript একটি High-Level, Interpreted, Dynamic Programming Language যা Browser এবং Server (Node.js) উভয় জায়গায় চলে।

Q2: JavaScript কি Compiled নাকি Interpreted?

JavaScript Interpreted — কিন্তু আধুনিক Engines (V8) JIT (Just-In-Time) Compilation ব্যবহার করে, তাই এটি দ্রুত।

Q3: Node.js কী?

Node.js হলো একটি Runtime Environment যা V8 Engine ব্যবহার করে Server-এ JavaScript চালায়।

Q4: V8 Engine কী করে?

V8 JavaScript কোডকে Machine Code-এ Convert করে যা Computer সরাসরি বুঝতে পারে।

Q5: JavaScript কে তৈরি করেছেন?

1995 সালে Brendan Eich মাত্র 10 দিনে JavaScript তৈরি করেছিলেন। তখন নাম ছিল Mocha, পরে LiveScript, তারপর JavaScript।
